# SisFall 낙상 탐지 기준 실험

SisFall 데이터로 낙상 탐지 방법을 비교한 기준 코드. 통계 방법, 비지도 머신러닝, 지도 머신러닝을 같은 조건에서 평가하고 판정 1회당 추론 속도를 함께 잰다.

SisFall은 **허리** 센서 데이터다. 안경(머리)에 그대로 옮길 수 없으므로 머리 센서가 있는 데이터로 다시 검증해야 한다.

## 데이터 준비

데이터는 저장소에 없다. `SisFall_Task specified` 폴더를 받아 아래 둘 중 하나로 둔다.

- 이 폴더의 `data/SisFall_Task specified`에 넣는다 (`.gitignore`에 등록돼 있어 올라가지 않는다)
- 다른 곳에 두고 환경 변수로 알려준다: `export SISFALL_DIR="/경로/SisFall_Task specified"`

구성: `Training/`(30명) · `Test/`(8명), 사람 단위로 미리 나뉘어 있다. 파일 하나가 시행 하나이고, 파일명 앞 글자가 `F`면 낙상, `D`면 일상동작이다.

**`FallCheck` 열은 낙상 라벨이 아니다.** 일상동작 파일까지 모든 파일의 마지막 1초(가속도 최고점 포함)가 1로 표시돼 있다.

## 환경

```bash
conda create -n somago -c conda-forge --override-channels python=3.11 llvm-openmp -y
conda activate somago
pip install -r requirements.txt
```

`llvm-openmp`가 없으면 macOS에서 LightGBM을 불러올 수 없다.

## 실행 순서

이 폴더에서 순서대로 실행한다. 뒤 스크립트가 앞 스크립트의 결과 파일을 읽는다.

| 스크립트 | 하는 일 | 걸리는 시간 |
|---|---|---|
| `01_baseline.py` | 판정 구간의 단일 지표(최고 가속도 등) 임계값 기준선 | 10초 |
| `02_statistical.py` | 통계 방법 3종 비교: 기준선, 자유낙하→충격 규칙, 마할라노비스 거리 | 10초 |
| `03_ml_features.py` | 모양 피처 추가, 비지도 2종 vs 지도 2종 | 20초 |
| `04_cnn.py` | 원신호를 그대로 넣는 1D CNN | 2분 |
| `05_speed.py` | 라이브러리 그대로 잰 추론 시간 (파이썬 호출 비용 포함) | 20초 |
| `06_speed_compiled.py` | 컴파일 구현·ONNX Runtime으로 잰 판정 1회 지연 | 30초 |
| `07_test_eval.py` | Test 평가 + 성능·속도 종합표 | 3분 |

공용 모듈: `sisfall.py`(데이터 로더·정제·피처), `evaluation.py`(평가 설계), `final_models.py`(최종 모델 학습).

## 평가 설계

모델을 돌리기 전에 정했다. 결과를 보고 바꾸지 않는다.

- **예측 단위**: 파일마다 마지막 1초(판정 구간)가 낙상인지 판정한다. 판정 직전 1초까지 쓰고, 판정 이후 데이터는 쓰지 않는다
- **정제**: 주 가속도계는 ADXL345(±16g) — MMA8451Q(±8g)는 낙상 파일 15%에서 상한에 걸린다. 100Hz로 기록된 Test/SA01 파일 12개는 200Hz로 보간한다. 판정 구간 앞 데이터가 1초 미만인 파일은 제외한다
- **검증**: Training 30명을 사람 단위 5묶음으로 나눈다. 같은 사람은 한 묶음에만 들어간다
- **지표**: 재현율 90/95/99%에 맞춘 지점의 특이도. 정확도·정밀도·F1은 쓰지 않는다 — Test의 낙상 비율(49%)이 현실과 달라 값이 왜곡된다
- **임계값**: Training 교차검증에서 정하고 Test에는 그대로 적용한다
- **Test**: 후보를 정한 뒤 한 번만 쓴다

## 결과

추론 지연은 판정 1회(원신호 2초 → 점수, 피처 계산 포함), 노트북 CPU 1스레드 중앙값. Test 재현율·특이도는 Training에서 정한 "재현율 95% 임계값"을 그대로 적용한 값이고, 괄호는 사람 단위 부트스트랩 95% 구간이다.

| 후보 | 추론 지연 | 모델 크기 | CV 특이도 | Test 재현율 | Test 특이도 |
|---|---|---|---|---|---|
| 기준선: 최고 가속도 | 0.3µs | 0.004KB | 0.746 ± 0.039 | 0.967 (0.947~0.987) | 0.676 (0.644~0.723) |
| 로지스틱 회귀 | 2.0µs | 0.05KB | 0.978 ± 0.022 | 0.913 (0.816~0.993) | 0.974 (0.954~0.993) |
| 오토인코더 | 2.8µs | 1.1KB | 0.833 ± 0.104 | 0.910 (0.820~1.000) | 0.814 (0.776~0.852) |
| LightGBM | 7.6µs | 50KB | 0.992 ± 0.009 | 0.950 (0.876~0.993) | 0.987 (0.977~0.997) |
| 1D CNN | 38µs | 38KB | 0.992 ± 0.006 | 0.950 (0.920~0.977) | 0.977 (0.947~0.997) |
| Isolation Forest | 1,487µs | 213KB | 0.938 ± 0.025 | 0.953 (0.913~0.993) | 0.899 (0.841~0.946) |

- 성능을 끌어올린 것은 모델 종류보다 **모양 피처**(회전각, 자세 변화, 직전 대비 충격 비율)다. 같은 LightGBM이 크기 피처만으로는 재현율 95%에서 특이도 0.865였다
- 비지도 방법은 "평소와 다르면 낙상"이라 격한 일상동작(조깅, 빠른 계단)을 낙상으로 오인한다
- 추론 시간은 **한 건씩, 피처 계산까지 포함해** 잰다. 여러 건을 묶어 재고 나누면 파이썬 호출 비용이 희석되어 순위가 뒤집힌다
